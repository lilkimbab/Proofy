# 문제 생성 · 피드백 API 비용 모델

이 문서는 월정액 상품을 만들 때 **문제 생성 + 피드백 파트가 한 달에 사용자 1명당 얼마까지 API 비용을 써도 되는지**를 계산하기 위한 기준이다.

가격과 모델 비용은 계속 바뀌므로, 아래 숫자는 2026-05-07 기준의 초기 운영 가정이다. 실제 출시 전에는 최신 API 가격, 환율, 결제 수수료, 서버 비용을 다시 넣어서 갱신해야 한다. 현재 코드는 이 문서의 숫자를 기본 제한값으로 쓰지 않는다. 실제 요금제와 사용자별 제한량은 추후 수익 계산과 운영 정책 논의 후 `.env`에서 켠다.

## 1. 결론

월 10,000원 상품은 가능하다. 다만 조건이 있다.

- `gpt-5.5`를 모든 요청에 쓰면 안 된다.
- 객관식 채점과 일반 피드백은 최대한 코드/템플릿으로 처리한다.
- 일반 문제 생성은 `gpt-5.4-mini`를 기본으로 둔다.
- `gpt-5.5`는 고난도 시험 대비, 복잡한 주관식 채점, 품질 검증 재시도에만 제한적으로 쓴다.
- 사용자 1명당 전체 AI/API 원가는 월 2,000원 안쪽을 목표로 둔다.
- 그중 문제 생성 + 피드백 파트는 월 1,100원 안쪽을 목표로 둔다.

따라서 계산 예시는 다음과 같다. 확정 가격이나 확정 제한량이 아니다.

| 상품 | 월 가격 | 목적 | 내부 AI/API 목표 원가 |
| --- | ---: | --- | ---: |
| 체험/무료 | 0원 | 기능 맛보기, 제한된 데모 | 0~300원 |
| 기본 | 9,900~10,000원 | 일반 학생의 평소 학습 | 2,000원 이하 |
| 시험 대비 | 14,900~19,000원 | 고난도 문제와 주관식 채점이 많은 사용자 | 4,000~5,000원 이하 |
| 추가 시험 팩 | 3,000~5,000원 | 특정 시험 기간의 심층 문제/채점 추가 | 판매가의 40% 이하 |

현실적으로는 **월 9,900원은 출시용 진입 가격**, **월 12,900원은 더 안전한 기본 가격**, **월 19,000원은 시험 대비 고급 요금제**로 보는 것이 좋다.

## 2. 경쟁 서비스 기준

공개 가격을 기준으로 보면, 학습 서비스와 범용 AI 서비스의 가격대가 나뉜다.

| 서비스 | 공개 가격대 | 해석 |
| --- | ---: | --- |
| Quizlet Plus | 연간 결제 기준 월 약 $2.99~$3.75 | 플래시카드/연습 중심의 저가 학습 도구 |
| Khanmigo | 학습자/부모 기준 $4/month | Khan Academy 콘텐츠 기반 AI 튜터 |
| Google NotebookLM | 무료 Standard부터 Google AI Plans 기반 Plus/Pro/Ultra까지 | 문서 기반 학습/연구, flashcards/quizzes/audio/video/mind map 강점 |
| ChatGPT Plus | $20/month | 범용 AI, API 사용량은 별도 과금 |
| Claude Pro | $20/month, Max는 $100/month부터 | 범용 AI, 고사용량은 더 비싼 요금제로 분리 |

이 기준에서 월 10,000원은 약 $6~7 수준이다. Quizlet/Khanmigo보다는 비싸지만 ChatGPT/Claude/Google AI Pro보다는 훨씬 낮다. 따라서 우리 서비스가 월 10,000원을 유지하려면 “무제한 AI 사용권”이 아니라 **자료 기반 문제 생성, 오답 피드백, 시험 대비 학습 흐름을 적절한 한도 안에서 제공하는 상품**이어야 한다.

NotebookLM은 무료 한도와 Google AI Plans 번들이 강하기 때문에, 단순 문서 요약/플래시카드/퀴즈만으로는 가격 경쟁이 어렵다. 우리 가격표에서는 `시험 대비 문제 생성`, `주관식 rubric 채점`, `오답 맞춤 연습`, `약점 누적`을 전면에 세워야 한다. 자세한 경쟁 분석은 [notebooklm-competitive-analysis.md](notebooklm-competitive-analysis.md)에 정리한다.

## 3. 환율과 매출 가정

보수적으로 계산하기 위해 1 USD = 1,500원으로 둔다.

월 10,000원 상품을 카드 결제로 판다고 가정하면 대략 다음과 같다.

| 항목 | 금액 |
| --- | ---: |
| 사용자 결제 금액 | 10,000원 |
| 부가세 포함 가격이면 공급가 | 약 9,091원 |
| 결제 수수료 3.3% 가정 | 약 -330원 |
| 결제 후 남는 금액 | 약 8,760원 |
| 서버/DB/스토리지/로그/운영 여유분 | -1,500~2,000원 |
| 다른 팀 API 사용 여유분 | -700~900원 |
| 문제 생성 + 피드백 API 목표 예산 | -1,100원 |
| 남겨야 할 최소 이익/예비비 | 약 3,500~4,500원 |

그래서 10,000원 요금제에서 전체 AI/API 비용은 월 2,000원을 목표로 잡는 것이 안전하다. 아무 제한 없이 월 4,000~5,000원씩 API를 쓰면 서버비와 운영비를 고려했을 때 이익이 거의 남지 않는다.

## 4. OpenAI 모델별 비용 기준

현재 코드의 기본 모델 라우팅은 비용 관점에서 적절하다.

| 용도 | 기본 모델 | 이유 |
| --- | --- | --- |
| 일반 문제 생성 | `gpt-5.4-mini` | 품질과 비용 균형 |
| 고난도 문제 생성/품질 검증 | `gpt-5.5` | `hard`, `target_rigor=high`, `depth=deep`, 분석/평가형처럼 복잡한 추론이 필요한 경우 |
| 객관식 채점 | 코드 | 비용 0원, 결과 결정적 |
| 객관식 피드백 | 템플릿 기본, 필요 시 `gpt-5.4-nano` | 짧고 반복되는 문장은 저가 모델 또는 코드가 적합 |
| 일반 주관식 채점 | `gpt-5.4-mini` | rubric 기반 채점에 충분한 기본값 |
| 고난도/애매한 주관식 채점 | `gpt-5.5` | 점수 신뢰도가 중요한 경우에만 사용 |
| 학습 콘텐츠 생성 | `gpt-5.4-mini` | 대량 생성에 적합 |

공식 가격 기준으로 보면 `gpt-5.5`는 입력 $5/1M tokens, 출력 $30/1M tokens다. `gpt-5.4-mini`는 입력 $0.75/1M tokens, 출력 $4.50/1M tokens이고, `gpt-5.4-nano`는 입력 $0.20/1M tokens, 출력 $1.25/1M tokens다.

즉 `gpt-5.5` 출력 토큰은 `gpt-5.4-mini`보다 약 6.7배 비싸다. 그래서 고난도 요청이 아닌데 `gpt-5.5`를 쓰면 월정액 모델이 금방 무너진다.

## 5. 요청 1회당 대략 원가

아래 계산식:

```text
원가(원) = ((입력 토큰 / 1,000,000) * 입력 단가 + (출력 토큰 / 1,000,000) * 출력 단가) * 1,500
```

| 작업 | 모델 | 토큰 가정 | 예상 원가 |
| --- | --- | --- | ---: |
| 객관식/퀴즈 5문제 생성 | `gpt-5.4-mini` | 입력 6k, 출력 3.5k | 약 30원 |
| 일반 주관식 3문제 생성 | `gpt-5.4-mini` | 입력 7k, 출력 3.5k | 약 32원 |
| 심층 시험 주관식 3문제 생성 | `gpt-5.5` | 입력 8k, 출력 4k | 약 240원 |
| 일반 주관식 답안 채점 1회 | `gpt-5.4-mini` | 입력 4k, 출력 0.8k | 약 10원 |
| 고난도/애매한 주관식 채점 1회 | `gpt-5.5` | 입력 5k, 출력 1k | 약 83원 |
| 짧은 피드백 문체 보정 1회 | `gpt-5.4-nano` | 입력 2k, 출력 0.4k | 약 1~2원 |
| 개념 카드/OX/빈칸 등 콘텐츠 묶음 | `gpt-5.4-mini` | 입력 5k, 출력 2k | 약 19원 |
| Tutor/Q&A 1회 | `gpt-5.4-mini` | 입력 3k, 출력 0.8k | 약 9원 |

이 표에서 중요한 점은 두 가지다.

첫째, 일반 문제 생성과 일반 피드백은 생각보다 싸다.  
둘째, `gpt-5.5` 기반 심층 문제 생성과 고난도 주관식 채점은 누적되면 빠르게 비싸진다.

## 7. 한도 산정용 시나리오

아래 표는 수익 계산을 시작할 때 넣어볼 수 있는 **산정 예시**다. 현재 단계에서 확정 한도나 기본값으로 적용하지 않는다. 실제 제한량은 결제 가격, 사용자당 평균 사용량, 다른 팀 API 비용, 서버/DB 비용을 합쳐 계산한 뒤 `.env`에서 켠다.

| 기능 | 월 한도 |
| --- | ---: |
| 일반 문제 생성 묶음 | 10회 |
| 묶음당 문제 수 | 최대 5문제 |
| 심층 시험 문제 생성 | 2회 |
| 일반 주관식 채점 | 30회 |
| 고난도/애매한 주관식 채점 | 5회 |
| 개념 카드/OX/빈칸 등 학습 콘텐츠 생성 | 10~20회 |
| Tutor/Q&A | 다른 팀과 합쳐 월 80~120회 |
| 객관식 채점/템플릿 피드백 | 비용 영향이 작아 넓게 제공 가능 |

이 숫자를 그대로 사용자에게 보여주지 않는다. 실제 상품화 단계에서는 내부 credit 또는 기능별 사용량 정책으로 바꾸고, 사용자가 이해하기 쉬운 문구만 프론트에 제공한다.

예:

| 작업 | 내부 credit |
| --- | ---: |
| 객관식/퀴즈 5문제 생성 | 2 |
| 일반 주관식 3문제 생성 | 2 |
| 심층 시험 문제 3문제 생성 | 15 |
| 일반 주관식 채점 | 1 |
| 고난도 주관식 채점 | 5 |
| 학습 콘텐츠 묶음 생성 | 1 |
| Tutor/Q&A | 1 |

credit 값도 확정이 아니다. 지금 코드는 `PROBLEM_GENERATION_MONTHLY_LIMIT`, `PROBLEM_GENERATION_HIGH_RIGOR_MONTHLY_LIMIT`, `LLM_MONTHLY_USER_BUDGET_KRW`, `LLM_ENFORCE_MONTHLY_BUDGET`만 준비해 두고, 기본값은 모두 비활성 상태로 둔다.

## 8. 초과 사용 시 동작

비용을 막기 위해 초과 사용자를 바로 차단하기보다 단계적으로 낮춘다. 아래 단계도 운영 정책 예시이며, 실제 기준선은 추후 수익 계산 후 정한다.

1. `gpt-5.5` 호출 한도 초과
   - `gpt-5.4-mini` 또는 `gpt-5.4`로 낮춘다.
   - “심층 검토는 이번 달 한도를 넘었어요. 기본 품질로 먼저 만들어볼게요.”처럼 안내한다.

2. 월 AI/API 예산 80% 도달
   - 검색 chunk 수를 줄인다.
   - 출력 길이를 줄인다.
   - 후보 문제 수를 줄인다.
   - 고난도 품질 재시도 횟수를 줄인다.

3. 월 AI/API 예산 100% 도달
   - 객관식 코드 채점, 기존 문제 복습, 오답노트 조회처럼 비용이 낮은 기능은 계속 제공한다.
   - 새 고난도 문제 생성과 LLM 주관식 채점은 다음 달 또는 추가 팩으로 넘긴다.

## 9. 다른 팀 API 비용 배분

10,000원 요금제 기준으로 전체 AI/API 예산을 2,000원으로 잡으면, 팀별 권장 배분은 아래 정도가 적당하다.

| 파트 | 월 사용자당 목표 예산 | 비고 |
| --- | ---: | --- |
| 문제 생성 + 피드백 | 1,100원 | 심층 문제/주관식 채점이 핵심 비용 |
| Tutor/Q&A | 500~700원 | 질문 수가 많아질 수 있어 별도 한도 필요 |
| 자료 생성/요약/로드맵 | 200~400원 | 업로드 빈도에 따라 변동 |
| OCR/vision | 별도 측정 필요 | 이미지 기반이면 비용이 커질 수 있음 |

OCR/vision과 문서 구조화는 자료 업로드 시 한 번에 큰 비용이 나갈 수 있다. 따라서 자료 업로드는 월 개수 제한 또는 파일 크기 제한을 따로 둬야 한다.

## 10. 현재 코드 기준 권장 설정

현재 `.env.example`의 방향은 유지한다.

```text
PROBLEM_MODEL=gpt-5.4-mini
PROBLEM_QUALITY_MODEL=gpt-5.5
LEARNING_CONTENT_MODEL=gpt-5.4-mini
LEARNING_CONTENT_QUALITY_MODEL=gpt-5.5
FEEDBACK_MODEL=gpt-5.4-nano
GRADING_MODEL=gpt-5.4-mini
GRADING_QUALITY_MODEL=gpt-5.5
MULTIPLE_CHOICE_FEEDBACK_LLM_ENABLED=false
LLM_CHUNK_CHAR_LIMIT=1800
LLM_MAX_OUTPUT_TOKENS_PROBLEM=2500
LLM_MAX_OUTPUT_TOKENS_LEARNING_CONTENT=1800
LLM_MAX_OUTPUT_TOKENS_FEEDBACK=900
LLM_REASONING_EFFORT_PROBLEM=low
LLM_REASONING_EFFORT_PROBLEM_QUALITY=medium
LLM_REASONING_EFFORT_LEARNING_CONTENT=low
LLM_REASONING_EFFORT_FEEDBACK=low
```

바꾸지 말아야 할 것:

- 객관식 채점을 LLM으로 바꾸지 않는다.
- 모든 문제 생성을 `gpt-5.5`로 올리지 않는다.
- 피드백 문장 하나 만들려고 매번 비싼 모델을 부르지 않는다.
- Search/RAG chunk를 너무 많이 넣지 않는다.

추가로 필요한 운영 기능:

- 사용자별 월 API 사용량 집계
- 기능별 token 사용량 집계
- 사용량 요약은 목록 조회 limit에 의존하지 않고 DB aggregate로 전체 기간을 합산한다.
- `LLM_ENFORCE_MONTHLY_BUDGET`로 월 LLM 예산 초과 시 새 문제 생성, LLM 기반 피드백, LLM 기반 학습 콘텐츠 생성 차단
- `PROBLEM_GENERATION_MONTHLY_LIMIT`로 월 문제 생성 수 제한
- `PROBLEM_GENERATION_HIGH_RIGOR_MONTHLY_LIMIT`로 hard/deep/시험형 문제 생성 수 별도 제한
- 주관식 채점 재시도 방지
- 비용 80% 도달 시 자동 downgrade
- 비용 100% 도달 시 고비용 기능 제한
