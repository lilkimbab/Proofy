# 팀 전체 기능 구조와 역할 분담

이 문서는 AI 학습 에이전트 서비스의 전체 기능 구조와 팀원별 역할 경계를 정리한 기준 문서다.

앞으로 문제 생성 + 피드백 파트를 구현할 때는 이 문서를 기준으로 **내가 직접 구현할 범위**와 **다른 팀 파트와 연동할 범위**를 구분한다.

---

## 1. 자료 생성

담당: 조유찬

목표:

- 사용자가 업로드한 PDF, 이미지, 텍스트 자료를 학습 가능한 구조화 문서로 바꾼다.
- 섹션 단위로 나누고, 각 섹션에 대한 설명, 요약, 예시를 만든다.
- 이후 RAG/Search Agent가 사용할 수 있도록 chunk 단위로 넘긴다.

기능:

- PDF → 구조화 문서 생성
- 섹션 나누기
- 섹션별 설명 생성
- 섹션별 요약 생성
- 예시 생성
- RAG 연결을 위한 chunk 생성

흐름:

```text
User → PDF 업로드
  ↓
Guard Agent (파일 검증)
  ↓
Document Agent
  ├─ 섹션 분리
  ├─ 설명 생성
  ├─ 요약 생성
  ├─ 예시 생성
  ↓
Search Agent → embedding 저장
  ↓
Vector DB
```

문제 생성 + 피드백 파트와의 연결:

- 문제 생성 파트는 Document Agent를 직접 구현하지 않는다.
- 문제 생성 파트는 Document Agent가 만든 chunk를 Search Agent를 통해 받아 사용한다.
- 문서 전체의 분야, 주제, 섹션 분류 metadata는 자료 생성 파트가 제공하는 값을 우선 사용한다.
- 문제 생성 파트는 분야 분류기가 아니라, 전달받은 chunk로 어떤 문제/학습 콘텐츠를 만들 수 있는지 판단하는 출제 전략 선택만 담당한다.

---

## 2. 문제 생성

담당: 박준

목표:

- 사용자가 업로드한 자료를 기반으로 문제를 생성한다.
- 문제는 Search Agent가 가져온 자료 chunk에 근거해야 한다.
- 객관식, 주관식부터 MVP로 구현하고, 이후 개념 카드, 빈칸 문제, OX 문제, 오답 맞춤 연습, 미니 모의고사로 확장한다.

기능:

- 문제 생성
- 정답 생성
- 해설 생성
- 보기별 해설 생성
- 문제 유형 선택
- 난이도 조절
- 자료 기반 출처 연결
- RAG 연결

흐름:

```text
User → "문제 만들어줘"
  ↓
Guard Agent
  ↓
Search Agent (개념 가져오기)
  ↓
Problem Agent
  ├─ 문제 생성
  ├─ 정답 생성
  ├─ 해설 생성
  ├─ 유형 선택 (객관식/주관식 등)
  ├─ 난이도 조절
  ↓
Personalization Agent
  ↓
Response
```

박준이 직접 구현할 것:

- `ProblemAgent`
- 문제 생성 프롬프트
- 문제 출력 schema
- 정답/해설/rubric 생성
- 문제 품질 검증
- 문제 생성 API
- 문제 생성 결과 저장 계약

박준이 직접 구현하지 않는 것:

- Vector DB
- Search Agent 내부 검색 로직
- Personalization Agent 전체 로직
- 사용자 계정 DB

---

## 3. 피드백 생성

담당: 박준

목표:

- 사용자가 제출한 답안과 풀이를 분석한다.
- 단순히 맞고 틀림을 알려주는 것이 아니라, 어디서 왜 틀렸는지 설명한다.
- 오답 유형, 약점 개념, 복습 추천을 만들어 User Model 또는 Roadmap Agent가 사용할 수 있게 한다.

기능:

- 객관식 코드 채점
- 주관식 LLM 채점
- 태블릿 필기 답안 채점 준비
- 오답 분석
- 풀이 분석
- 개념 오류 탐지
- 개선 방향 제시
- 복습 추천 생성
- RAG 연결

흐름:

```text
User → 풀이 제출
  ↓
Guard Agent
  ↓
Search Agent (정답 + 개념)
  ↓
Feedback Agent
  ├─ 오답 분석
  ├─ 풀이 분석
  ├─ 개념 오류 탐지
  ├─ 개선 방향
  ↓
Personalization Agent
  ↓
User Model 업데이트
```

주관식 답안 처리:

```text
타자 입력 답안
  ↓
문제 + 모범답안 + rubric + 자료 context + 사용자 답안
  ↓
LLM 채점
  ↓
점수 + 피드백 + 약점 개념 + 복습 추천
```

```text
태블릿 필기 답안
  ↓
필기 이미지 또는 펜 입력
  ↓
OCR/vision으로 텍스트 변환
  ↓
문제 + 모범답안 + rubric + 자료 context + 변환된 답안
  ↓
LLM 채점
  ↓
점수 + 피드백 + 약점 개념 + 복습 추천
```

박준이 직접 구현할 것:

- `FeedbackAgent`
- 객관식 채점 로직
- 주관식 rubric 기반 채점 로직
- 피드백 생성 프롬프트
- 오답 유형 분류
- 약점 개념 추출
- 복습 추천 생성
- 답안 제출 API
- 피드백 저장 계약
- User Model 업데이트 payload

박준이 직접 구현하지 않는 것:

- OCR/vision 전체 파이프라인
- 사용자 계정/개인정보 DB
- Roadmap Agent 내부 로직
- Personalization Agent 전체 로직

## 4. 로드맵 구성

담당: 조유찬

목표:

- 자료 생성에서 만든 구조화 문서를 바탕으로 학습 로드맵을 만든다.
- 사용자의 학습 패턴과 약점을 반영한다.
- 학습 진행에 따라 계획을 업데이트한다.

기능:

- 학습 로드맵 생성
- 사용자 학습 패턴 분석
- 학습 전략 생성
- 학습 경과 업데이트
- RAG 연결

흐름:

```text
User → 학습 요청
  ↓
Orchestrator
  ↓
Document Agent (전체 구조 분석)
  ↓
Personalization Agent (약점 분석)
  ↓
Roadmap Agent
  ├─ 학습 순서 구성
  ├─ 목표 설정
  ├─ 복습 전략
  ↓
Response
```

문제 생성 + 피드백 파트와의 연결:

- 피드백 결과에서 나온 약점 개념, 오답 유형, 복습 추천을 Roadmap Agent가 사용할 수 있다.
- 박준 파트는 로드맵을 직접 생성하지 않고, 로드맵 업데이트에 필요한 데이터를 제공한다.

---

## 5. 질의응답

담당: 한상훈

목표:

- 사용자가 업로드한 자료를 기반으로 질문에 답변한다.
- 자료 내 관련 위치를 찾아 설명한다.
- 사용자 수준에 맞게 설명 난이도를 조절한다.

기능:

- 사용자 자료 기반 답변
- 자료 위치 기반 질문 답변
- 관련 내용 연결
- 난이도 조절 설명
- 예시 생성
- RAG 연결

흐름:

```text
User → 문서 드래그 후 질문
  ↓
Guard Agent (질문 필터)
  ↓
Orchestrator
  ↓
Search Agent
  ├─ span 기반 context 검색
  ├─ 관련 개념 검색
  ↓
Tutor Agent
  ├─ 설명 생성
  ├─ 난이도 조절
  ├─ 예시 생성
  ↓
Personalization Agent
  ├─ 사용자 수준 반영
  ↓
Response
  ↓
Annotation 저장
```

문제 생성 + 피드백 파트와의 연결:

- 문제 해설이나 피드백 말투는 Personalization Agent와 연결될 수 있다.
- 박준 파트는 질의응답 Agent를 직접 구현하지 않는다.

---

## 6. Guard/Harness Agent

담당: 한상훈

목표:

- 이상한 질문이나 부적절한 요청을 필터링한다.
- 교육 범위를 유지한다.
- 할루시네이션을 줄인다.

기능:

- 파일 검증
- 질문 필터링
- 교육 범위 유지
- 프롬프트 인젝션 방어
- 할루시네이션 감소

문제 생성 + 피드백 파트와의 연결:

- 문제 생성 요청 전 Guard Agent를 통과해야 한다.
- 답안 제출 전 Guard Agent를 통과해야 한다.
- 박준 파트는 Guard Agent 전체를 구현하지 않고, Guard 결과를 받아 처리한다.

---

## 7. Search Agent

담당: 김태훈

목표:

- Vector DB에서 관련 자료 chunk를 검색한다.
- 문제 생성, 피드백, 질의응답, 로드맵이 사용할 context를 제공한다.

기능:

- embedding 저장
- vector DB 검색
- 관련 chunk 반환
- chunk ID 기반 재조회

문제 생성 + 피드백 파트와의 연결:

- 박준 파트는 Search Agent 내부를 구현하지 않는다.
- 박준 파트는 Search Agent의 입력/출력 계약만 맞춘다.

필요한 Search Agent 응답:

```json
{
  "chunk_id": "chunk_001",
  "document_id": "doc_001",
  "content": "자료 원문 또는 정리된 chunk 내용",
  "page": 12,
  "section_title": "섹션 제목",
  "concepts": ["관련 개념"]
}
```

---

## 8. Personalization Agent

담당: 한상훈

목표:

- 같은 설명이나 피드백을 사용자 수준에 맞게 바꾼다.
- 초보자에게는 직관적이고 쉬운 설명을 제공한다.
- 고급자에게는 수식 중심, 압축된 설명을 제공한다.

기능:

- 사용자 수준 반영
- 설명 스타일 변환
- 피드백 말투 조정
- 난이도 조절

문제 생성 + 피드백 파트와의 연결:

- 박준 파트는 기본 문제/피드백을 생성한다.
- 최종 문장 스타일 변환은 Personalization Agent와 연결될 수 있다.
- MVP에서는 박준 파트가 기본 친절한 말투를 직접 제공하고, 이후 한상훈 파트와 분리한다.

---

## 9. 사용자 계정/개인정보 DB

담당: 왕호진

목표:

- 사용자 계정, 개인정보, 인증 정보를 관리한다.

문제 생성 + 피드백 파트와의 연결:

- 박준 파트는 사용자 계정 DB를 직접 구현하지 않는다.
- MVP에서는 `X-User-Id` 헤더로 사용자 ID를 받는다.
- 최종 통합에서는 왕호진 파트의 인증/사용자 시스템에서 user_id를 받는다.

---

## 최종 역할 요약

```text
자료 생성 + 로드맵 → 조유찬
데이터베이스 + 서치 → 김태훈
문제 생성 + 피드백 → 박준
질의응답 + Guard + Personalization Agent → 한상훈
사용자 계정/개인정보 DB → 왕호진
```

박준 파트의 핵심 책임:

```text
Search Agent에서 자료 chunk를 받아온다.
LLM으로 문제, 정답, 해설, rubric을 생성한다.
객관식은 코드로 채점한다.
주관식은 LLM으로 rubric 기준 채점한다.
피드백과 오답 분석 결과를 만든다.
DB/Search/User Model 파트와 주고받을 데이터 계약을 맞춘다.
```
